# KSCOLD Agent 구조

`apps/agent/src/agent`는 Vault 검색, 블로그·피드 지식 검색, 피드 초안 작성 기능을 하나의 Agent 런타임으로 묶습니다.

## 실행 경로

```text
Spring API → gRPC → server → application → graph / skills → tools → MongoDB · Qdrant · OpenAI
```

## 폴더별 책임

| 경로           | 책임                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| `application/` | gRPC 요청을 유스케이스로 조합하고 실행 수명주기를 관리합니다.                      |
| `graph/`       | Vault·블로그·피드 검색 답변을 위한 LangGraph 상태, 노드, 워크플로를 둡니다.        |
| `skills/`      | 피드 초안처럼 목적이 분명한 기능을 독립 스킬로 관리합니다.                         |
| `tools/`       | 검색, 권한 필터, 색인, 출처, 웹 검색, 관측처럼 외부 자원에 접근하는 도구를 둡니다. |
| `prompts/`     | LLM 시스템 지시문과 응답 형식을 코드 흐름과 분리해 관리합니다.                     |
| `server/`      | gRPC 서버 기동과 protobuf 입출력 변환만 담당합니다.                                |
| `grpc/`        | 빌드 시 protobuf에서 생성되는 Python 파일의 위치입니다.                            |

## gRPC 기능

| RPC                   | 역할                                                            |
| --------------------- | --------------------------------------------------------------- |
| `Chat` · `ChatStream` | Vault·블로그·피드 문맥을 검색해 답변과 출처를 반환합니다.       |
| `PageChatStream`       | 요청에 담긴 페이지 자료만 설명하며 검색·색인·대화 저장을 하지 않습니다. |
| `Search`              | 검색어, 콘텐츠 유형, 결과 개수에 따라 문서 발췌문을 반환합니다. |
| `CreateFeedPlan`      | 피드 주제와 참고 자료를 분석해 작성 계획을 만듭니다.            |
| `CreateFeedDraft`     | 승인된 계획과 검색 문맥으로 피드 초안을 만듭니다.               |
| `Reindex`             | MongoDB 문서를 다시 읽어 Qdrant 검색 색인을 동기화합니다.       |

## 검색과 색인

- 의미 검색은 Qdrant 벡터를 사용하고, 벡터 검색을 사용할 수 없으면 MongoDB 키워드 검색으로 대체합니다.
- `Search`는 Vault·블로그·피드 콘텐츠 유형을 구분하고 요청된 범위 밖의 문서를 결과에서 제거합니다.
- 서버 시작 시 MongoDB 원문과 Qdrant 색인의 차이를 계산해 새 문서와 변경 문서만 반영합니다.
- 검색 응답은 원문 전체가 아니라 제목, 경로, 콘텐츠 유형, 짧은 발췌문과 점수만 반환합니다.
- 공개 Vault 검색은 공개 문서만 조회하며 관리자 전용 데이터는 권한 필터를 통과한 요청에만 제공합니다.

## 작성 원칙

- `server`는 검색·생성 규칙을 직접 갖지 않고 `application`만 호출합니다.
- `graph`는 상태 전이와 도구 호출 순서만 결정합니다.
- `tools`는 데이터를 찾거나 바꾸는 일만 맡고, 사용자 문장을 직접 결정하지 않습니다.
- 프롬프트 수정은 `prompts`에서만 수행해 기능 코드와 문구를 분리합니다.
- 새 기능은 먼저 `skills/<기능명>`으로 만들고, 공용 검색은 기존 `tools`를 재사용합니다.
- 기존 블로그 MongoDB 컬렉션은 읽기 중심으로 사용하며, Agent 기록은 전용 컬렉션에만 남깁니다.
- Qdrant는 파생 색인이므로 원본으로 취급하지 않으며 MongoDB 문서에서 언제든 재생성할 수 있어야 합니다.
- 장애 시 검색 대체 경로를 유지하고 출처 없는 답변을 생성하지 않습니다.

## 일회성 페이지 Agent

- Spring의 별도 페이지 질문 유스케이스는 사용자·열람권한·대화 저장 포트를 받지 않습니다.
- 페이지 제목·섹션·짧은 대화 문맥은 인용 자료로만 취급하며 시스템 지시나 사용자 권한으로 승격하지 않습니다.
- 문서·벡터·웹 도구를 호출하지 않고 원문 섹션의 상대 경로와 앵커만 출처로 반환합니다.
- 질문 1200자, 섹션 6개·각 6000자·합계 16000자, 대화 6개·합계 3600자로 제한합니다.
- API 본문은 96KiB, IP 해시별 분당 8회·전체 분당 30회·UTC 일일 기본 200회·동시 실행 2개로 제한합니다. 일일 한도는 `vault.agent.page-chat-daily-request-limit`로 조정하며 서버 재시작 시 초기화되는 단일 인스턴스 메모리 한도입니다.
- 비용 제한 키는 User-Agent를 사용하지 않습니다. 기본은 연결 IP만 신뢰하고, `vault.agent.page-chat-trusted-proxy-addresses`에 정확한 프록시 IP를 지정한 경우에만 전달 체인을 오른쪽부터 검증합니다. 미설정 프록시 뒤의 방문자는 보수적으로 하나의 IP 한도를 공유합니다.
- 외부 생성은 최대 900토큰·응답 3600자, HTTP 연결 5초·첫 응답 및 청크 읽기 20초·gRPC 최대 60초이며 재시도하지 않습니다.
- Python 페이지 스킬도 실제 공급사 요청을 동시 2개로 제한합니다. 초기 HTTP 응답 대기 중 취소는 즉시 닫을 스트림 핸들이 없으므로 요청이 실제 종료할 때까지 슬롯을 유지합니다. 일반 Agent의 공유 HTTP 클라이언트는 닫지 않습니다.
- 브라우저 연결 종료와 시간 초과는 gRPC 취소 및 응답 스트림 닫기로 연결합니다.
- 외부 공급사 요청은 `store=False`이며 사이트 MongoDB에 질문·답변·실행 기록을 저장하지 않습니다. 공급사 안전 모니터링 보존 정책은 별개입니다.
- 기존 Agent의 시작 시 색인 동기화·일반 대화 권한·대화 저장 흐름은 변경하지 않습니다.
